# Outreach + Discovery/Enrichment Audit — July 2026

Multi-agent audit (7 subsystem auditors, every finding adversarially verified against the code
by an independent agent; 0 findings refuted). 44 confirmed + 12 partially-confirmed findings.
This file is the durable work queue. Severity reflects impact on a REAL keyed production deploy.

Legend: **bug** = incorrect behavior · **gap** = built but unwired/incomplete · **feature** = missing capability.
"(partial)" = verified real but overstated/mitigated — read the note.

---

## Tier 0 — "sends that never happened" (fix before any real go-live)

These combine into one failure class: **production can report success while nothing was delivered.**

1. **[bug/high] `send()` treats a `failed` SendResult as sent** — `pipeline.ts:562-572` special-cases
   only `bounced`. SMTP auth/TLS/network errors and any Gmail/Graph non-2xx return `failed`
   (`mailbox.ts:165,51,72`) and fall into the success branch: message marked `sent` + `sentAt`,
   prospect advanced to contacted/in_sequence, a `send` usageEvent billed, daily cap consumed.
   One SMTP outage "sends" the whole scored backlog. Fix: explicit `failed` branch — mark message
   failed with reason, don't advance, don't bill, leave retryable; back off after consecutive failures.

2. **[gap/high] Mailbox credentials live only in `InMemorySecretStore`** — `context.ts:249`; no
   persistent SecretStore even with `USE_POSTGRES`. After any API restart every `credentialsRef`
   dangles → `mailboxResolver` silently falls back to `MockMailboxSender` → outreach fabricates
   `sent` forever; `replyPoller` returns []. Fix: Postgres-backed encrypted SecretStore adapter
   (env-gated) + prod-mode fail-loud in `mailboxResolver` instead of mock fallback.

3. **[bug/high] Standalone worker (`npm run worker`) is entirely mock/synthetic** —
   `worker.ts:96-109` `buildDepsFromEnv`: `MockMailboxSender`, no `mailboxResolver`/`replyPoller`/
   `notifier`/secrets; `new SerpDiscoverySource()` (deterministic even when keyed); synthetic
   generators UNGATED by `allowSyntheticDiscovery` (invents prospects in prod); no backlink/YouTube/
   podcast sources; `StubEmailFinder` ignores `HUNTER_API_KEY`; no fetcher/verifier/enricher/relevance.
   **deploy/docker-compose.yml runs this worker as the production scheduler.** Fix: extract ONE shared
   env-gated dependency factory used by both `context.ts` and `worker.ts`.

4. **[gap/high] Transactional ESP never wired** — `context.ts:330` hardcodes
   `ConsoleTransactionalMailer`; `RESEND_API_KEY`/`POSTMARK_SERVER_TOKEN`/`ESP_PROVIDER` in
   .env.example are read nowhere; `ResendMailer`/`PostmarkMailer` have zero callers. Activation
   welcome + affiliate magic-link emails never leave the process in prod (and the console mailer
   returns "sent", stamping `activationEmailSentAt` so the idempotency guard blocks a later real
   send). Fix: gate the mailer by env in createContext + boot warning when unconfigured in prod.

## Tier 1 — reply-loop dangers (suppress the wrong people, email the wrong people)

5. **[bug/high] Bottom-quoted replies globally suppress interested prospects** —
   `extractReplyText` (`reply-ingestion.ts:35`) falls back to the FULL raw email when the new-text
   extraction is empty (any quote-first reply). The raw includes our own footer "Unsubscribe: reply
   STOP…", and `classifyReply` checks unsubscribe FIRST → "I'm interested!" bottom-posted = global
   suppression. Fix: never classify from raw fallback (route to review), strip our own footer shape.

6. **[bug/high] IMAP poller routes ANY inbox mail from a prospect's address** — no reply
   correlation (no In-Reply-To/References captured), no contacted-state check
   (`reply-router.ts:302`). The merchant's subscription to a prospect's newsletter (footer contains
   "unsubscribe") suppresses that hot prospect globally. Fix: capture In-Reply-To/References in
   `ImapMessage`, match against sent Message-Ids (needs #22 threading), require prospect state ∈
   {queued, contacted, in_sequence, replied}; everything else → "unmatched inbound" review queue.

7. **[bug/high] `processInboundReply` matches prospects across ALL tenants** — no merchantId
   filter (`reply-router.ts:302`); a reply to merchant A's mailbox can route to merchant B's
   prospect (wrong KB, wrong suppression, wrong meeting queue). ingestReplies knows
   `mailbox.merchantId` but doesn't pass it. Fix: scope the lookup by merchantId; resolve merchant
   from toEmail→mailbox for the public webhook.

8. **[bug/medium] "Reply STOP" is advertised but not honored** — `classifyReply` (`llm.ts:57`)
   has no bare-STOP rule → "STOP" classifies unknown → review, address stays emailable. Fix:
   deterministic short-circuit `/^stop\b/i` → unsubscribe, before any classifier.

9. **[bug/medium] Webhook paths have no Message-Id dedup** — dedup exists only in
   `ingestReplies`; both webhook routes discard the extracted messageId → ESP retries duplicate
   Reply/Meeting/Handoff/notification; webhook-delivered mail can be re-routed by the IMAP poll.
   Fix: centralize dedup inside processInboundReply/routeReply; stamp id at insert.

10. **[gap/medium] out_of_office "snooze" is a no-op** — no snoozeUntil stored; follow-ups keep
    firing on cadence while the person is away. Fix: persist snoozeUntil (default ~7d), skip in
    advanceSequences.

11. **[gap/high, partial] Long-tail "interested" replies + autopilot answers dead-end** —
    `self_serve` outcome (signupUrl) is discarded by every automated consumer; autopilot
    `autoSend:true` has zero consumers (documented-deferred, but the self-serve silence is not).
    The deterministic how_to_join answer never embeds the actual link. Fix: until the outbound-reply
    transport exists, create a handoff with a sendable draft for BOTH paths; embed signupUrl.

12. **[bug/high, partial] The self-serve signup URL is a fabricated dead link** —
    `merchantId.slice(-6)` matches no route; default base `https://app.vantage.dev` is not ours; no
    public /join web page exists. Latent (nothing sends it yet) but it's the URL the whole self-serve
    track depends on. Fix: build from config + full merchantId; add the public join page.

## Tier 2 — cap/deliverability enforcement holes

13. **[bug/high] Caps/warmup/auto-pause are not enforced on the mailbox that actually sends** —
    `capacityAvailable` gates on `pickSendableMailbox` (ANY mailbox) but `send()` always uses
    `campaign.mailboxId`; with 2+ mailboxes the campaign's box sends unbounded. `mailboxResolver`
    only refuses `disconnected`, so an auto-paused (`error`) mailbox keeps sending. `mailboxId:null`
    campaigns invent a from-address. Fix: gate on the campaign's own mailbox (status + remaining
    effective cap); resolver refuses `error`; refuse null-mailbox sends.

14. **[bug/medium] `pickSendableMailbox` hardcodes `ageDays=21`** — a day-0 warming mailbox gets
    cap 25 instead of 5; the warmup ramp is enforced everywhere EXCEPT where capacity is granted.
    `warmupStartedAt` is available. Fix: compute real ageDays (default 21 only when `ready`).

15. **[gap/medium] `launchCampaign` bypasses every guard** — no send window, no cap, no circuit
    check; route accepts `max` up to 10000; `respectLocalTime` never passed. Fix: apply the same
    guards as the autonomous path (ideally inside send()); default respectLocalTime.

16. **[bug/high] SMTP hard-bounce regex matches the port number** — `\b5\d\d\b` matches ":587" in
    `ECONNREFUSED …:587` → transient outage classified hard bounce → prospects mass-suppressed
    merchant-wide + bounce rate inflated toward auto-pause. Fix: classify from nodemailer
    `responseCode` (>=500) + textual markers; ECONNREFUSED/ETIMEDOUT/EAUTH = transient.

17. **[bug/medium] Circuit breaker counts unsubscribes as spam complaints over an ALL-TIME
    window** — normal 1-2% unsub rate trips the 0.3% FBL threshold; once open, sending halts so the
    denominator freezes → latches permanently. One-click unsubs (merchantId:null) aren't even
    counted. Fix: separate complaint reason (future FBL), rolling window, unsubs as a metric not a
    breaker input; attribute one-click unsubs via the `m=` param.

18. **[bug/medium] `/track/unsubscribe` is unsigned and destructive on GET** — anyone can globally
    suppress any address by enumeration; link-prefetchers (Outlook SafeLinks) silently unsubscribe
    recipients. The `m=` param is ignored. Fix: HMAC-signed token; GET renders a confirm page, POST
    (RFC 8058) stays one-click.

19. **[gap/high] `prospect.country` is never populated → GDPR/CASL geo gate + local-send-time gate
    are dead code** — enrich() resolves real geo into the profile but never copies it to the
    prospect. Fix: persist `country` from `profile.audience.primaryGeo` in enrich(); test that a
    DE/CA prospect is blocked.

## Tier 3 — outreach quality (reply-rate levers, cheap)

20. **[bug/medium] Follow-ups render `{{merchant}}`/`{{offer}}` as empty strings and skip
    personalization + A/B + pickVariant** — `automation.ts:197`. LLM-plan merchants get raw-template
    follow-ups; step-2+ variants silently ignored. Fix: build the same token set as queueFirstTouch
    and route through pickVariant + personalizeOutreach (with metering).

21. **[gap/medium] Follow-ups don't thread** — providerMessageId discarded at send; In-Reply-To/
    References never set; each step lands as a fresh cold email (worse replies + spam profile).
    Fix: persist providerMessageId on OutreachMessage; follow-ups use `Re:` + inReplyTo/references
    (SMTP transport already supports it). This also unblocks #6's reply correlation and in-product
    reply sending.

22. **[gap/medium, partial] MicrosoftGraphSender drops List-Unsubscribe/In-Reply-To entirely; OAuth
    rails never return `bounced`** — Graph rail violates the Gmail/Yahoo bulk-sender requirement the
    SMTP rail implements; OAuth-rail hard bounces never suppress. Fix: Graph raw-MIME send; map
    provider recipient errors → bounced; Gmail adds References.

23. **[improvement/low, partial] OAuth callback doesn't verify the granted account matches
    mailbox.email; token refresh has no per-mailbox serialization** (rotating MS refresh tokens can
    be clobbered). Fix at go-live: decode id_token + match; in-flight refresh promise map.

## Tier 4 — discovery correctness

24. **[bug/high] Deterministic SERP still runs (and fabricates prospects) when
    `ALLOW_SYNTHETIC_DISCOVERY=false`** — serpSource is never gated; with PROXY_URL set but no SERP
    key, the REAL proxy fetcher issues real HTTP to fabricated domains. Fix: omit serpSource when the
    provider is deterministic and synthetic is disallowed; choose fetcher per-source.

25. **[bug/high] Bare `amzn.to` short links are never detected** — the pattern requires `?tag=`,
    but real SiteStripe links carry no params → the most common affiliate link on the web yields
    zero signals (the synthetic generator fabricates `?tag=` so tests mask it). Fix: amzn.to =
    host-only HIGH match; keep ?tag= only for amazon.* full domains.

26. **[bug/high] Shared-network merchant-id backlink filter is a substring LIKE** — `m=1234`
    matches `m=12345`; network-targeted rows skip all client-side verification and are emitted
    `confirmedCompetitor` → the WRONG merchant's affiliates get the strongest scoring signal and
    outreach claims they promote the competitor (honesty violation). Fix: client-side exact-param
    post-filter before setting confirmedCompetitor.

27. **[bug/medium] SERP youtube `/watch` results collapse to one dead candidate** — candidateKey
    uses first path segment ("watch" for all) and cleanUrl strips `?v=` → paid youtube SERP budget
    produces ≤1 useless candidate. Fix: key/preserve video id; resolve to channel; add youtu.be.

28. **[bug/medium, partial] CompetitorProgramResolver scans the homepage first and trusts any
    network-shaped link** — a shared-network link to ANOTHER merchant resolves as "the competitor's
    program" and gets mined under their name (cached forever). Vanity/shared networks exploitable;
    self-hosted path is safe. Fix: PROGRAM_PATHS before homepage; require affiliate-ish anchor/HREF
    context; TTL the cache.

29. **[bug/low] Frontier depth under-counted on mixed-depth batches** — pooled tally + min-depth
    assignment lets expansion exceed maxDepth and corrupts Niche Map edges (discoveredFrom =
    mined[0]). Fix: per-node tally.

30. **[gap/medium, partial] Customer mining emits contact-less prospects ranked "priority 1"** —
    by design (hashed emails) but the planner rationale says "lowest-bounce" and billed enrichment
    runs on unreachable prospects. Fix: planner annotates/skips when only hashes exist.

## Tier 5 — enrichment correctness

31. **[bug/high] Identity merge over-merges distinct creators** — every page_link (0.5-confidence)
    account is a merge key, and query-stripping turns EVERY `youtube.com/watch?v=…` link into the
    shared key `url:https://youtube.com/watch` → two unrelated bloggers merge; scoring evidence ORs
    together; one creator silently drops from the pipeline. Fix: only merge on provenance
    seed/bio_aggregator/reciprocal (or confidence ≥0.85); classifyAccountUrl returns null for
    watch/shorts/playlist/embed paths and never attributes status/tweet URLs as owned accounts.

32. **[bug/medium] EnricherRegistry discards YouTube description emails/links when reach+engagement
    are null; CachingEnricher caches nulls (and transient errors) for 24h** — kills the exact
    "website-less YouTube creator" contact path. Fix: return metrics carrying ANY real data;
    don't cache transport errors (or short negative TTL).

33. **[bug/medium] Domain-level MX verifier outranks Hunter's mailbox-level verification** —
    with discovery keys + HUNTER_API_KEY set, every email is only MX-checked (any gmail.com guess
    passes) and Hunter's verify + its find-result `verified` flag are never used → hard bounces.
    Fix: Hunter verify when wired (MX as cheap pre-filter); trust the find candidate's status.

34. **[gap/medium] Obfuscated-email regex misses `name [at] domain.com`** (plain dot) — the most
    common single-obfuscation form is silently lost. Fix: allow a literal '.' alternative in the
    dot-part.

35. **[bug/medium] LlmRelevanceScorer caches transport failures as relevance 0 forever** — a
    transient LLM outage writes a confident 0 into the persisted score (-20 pts) with no
    unknownFactors entry; cache is poisoned per-process. Fix: don't cache the catch path; ideally
    return null → renormalize like other unknown signals.

36. **[gap/low] ScrapeMetricsEnricher passes non-ISO geo/language ("United States") into
    audienceOverlapScore which expects ISO codes** → in-market creators get the out-of-market
    penalty once the scrape key is wired. Fix: normalize or null.

37. **[improvement/low, partial] Per-candidate identity-merge scan is O(C×N) full-table** —
    bites at frontier-scale prospect counts. Fix: per-run identity-key index.

38. **[bug/medium, partial] Contact-resolver re-fetches the seed homepage** — visited-set key
    mismatch (bare host vs normalized URL) wastes 1 of 6 traversal fetches + duplicate verify calls
    (network cost absorbed by CachingFetcher, budget slot is not). Fix: consistent keys.

## Tier 6 — UI/wiring gaps (built server-side, unreachable by users)

39. **[gap/high] No campaign/sequence editor in the web app** — full CRUD API exists; the ONLY web
    reference to campaigns is read-only; the seeded demo campaign is the only way one exists. The
    core loop is unconfigurable without curl. Fix: Campaigns page (step editor with tokens, delays,
    channel email/dm, A/B variants, send window/cap, preview + content-scan, 3-5 cloneable
    templates from recommendedSequence).

40. **[gap/high] Replies can't be sent from inside the product** — Handoffs says "Approve & send"
    but only offers copy-to-clipboard; `autoSend:true` has no consumer; the transport already exists
    (mailboxResolver + In-Reply-To support). Fix: `POST /recruitment/handoffs/:id/send-reply`
    (editable, threaded via stored inbound Message-Id, resolves campaign mailbox) → then a unified
    inbox view; flips autopilot to real.

41. **[gap/medium] Mailbox OAuth connect has no UI button** — routes + token refresh done;
    Integrations.tsx says "coming in this build". Microsoft-detected merchants dead-end. Fix: the
    button + callback param handling (?connected=/?oauth_error=).

42. **[gap/medium] Five+ server endpoints have no UI caller** — ingest-replies ("check replies
    now"), content-scan, seed-test, dm-followup, personalization plan GET/PUT (merchants can never
    change their billed plan!), plus superseded prospect-level dm-queue/dm-draft/dm-sent routes.
    Fix: wire into existing pages; delete superseded routes.

43. **[gap/medium, partial] No merchantFaqs CRUD or aiSdrMode toggle in the UI** — the KB grounds
    on Program/Offer facts regardless (commission/cookie/payout/join answerable), but product/general
    questions always degrade to handoff and autopilot can't be enabled from the UI. Fix: KB card +
    mode select on Automation; seed demo FAQs.

44. **[gap/low] .env.example drift** — STRIPE/PAYPAL/WISE/REDIS/CF-KV vars are read nowhere;
    SLACK_WEBHOOK_URL (which IS read) is missing. Fix: annotate/remove + add.

45. **[improvement/low, partial] npm run demo drifted** — exercises none of the §16 outreach
    features; Handoffs/DmQueue render empty in the seeded demo; dead `void tickScheduler` import.

## Tier 7 — features worth adding (verified not-already-built + high value)

46. **[feature/high] Bulk import: prospect CSV + existing-affiliate roster** — no import path
    exists; blocks migration from Refersion/GRIN/ShareASale; also **without roster import, discovery
    can rediscover and cold-email the merchant's own current affiliates** (isExistingAffiliate only
    guards what's in the DB). Rows → ingestCandidate (dedup free, synthetic:false, source "import");
    historical produced_sales → ProspectOutcome to warm-start the learning loop.

47. **[feature/medium] Instagram/TikTok creator DISCOVERY source** — SCRAPE_API_URL is wired only
    for enrichment; the "social" channel in query-strategy is declared but never populated; the whole
    downstream (identity merge, DM queue) is already built for it. Add SocialCreatorDiscoverySource
    (hashtag/keyword) behind the existing key + `site:instagram.com` SERP fallback.

48. **[feature/medium] Content-freshness / activity signal** — a blog dead since 2021 scores like
    an active one; the dates are already fetched and discarded (YouTube publishedAt, RSS pubDate,
    DataForSEO first_seen/last_seen). Add nullable `activityRecency` factor + stale triage flag.

49. **[feature/medium] Merchant bookingUrl (calendar v1)** — the A-tier track currently persists a
    fabricated `https://cal.vantage.dev/...` stub link shown to the operator (honesty violation).
    Afternoon fix: `Merchant.bookingUrl` pasted at onboarding, used verbatim; CALCOM_API_KEY adapter
    later.

50. **[feature/low] Audience-quality flag** — pure heuristic over reach+engagement already held
    (flag >50k reach with <0.3% engagement), null when unknown; "suspicious audience" badge +
    nullable penalty factor.
